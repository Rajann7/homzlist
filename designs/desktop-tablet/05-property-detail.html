05 · Property detail
Real structure from detailBody.tsx: spec strip → section rail (Overview · About · field groups · Amenities · Seller) → About this property → the seller's own answer groups → Amenities → Posted by → Location (Area · Pincode · Property type) → Similar properties. No map, as in the app.

A · Buyer view — Desktop 1440 (sticky contact panel)

Decisions

  • Gallery, not a full-bleed hero. Mobile shows one swipeable photo. Desktop shows the primary photo plus two thumbs and an "All 14 photos" button that opens the same lightbox the app already has — a 9:16-era hero stretched to 1440 is the exact failure this set exists to avoid.
  • The contact box becomes a sticky panel (360). On mobile the Call / WhatsApp / Request Number buttons live in a bottom bar because the page is one long scroll. On desktop they pin beside the content, so the decision is reachable from any point in a very long detail page. Below 1200 the mobile bottom bar comes back exactly as it is.
  • The section rail becomes a sticky sub-nav. It already exists in the app (SectionRail) — here it stays visible while scrolling, which is what makes a twenty-seven-field Flat readable on desktop.
  • Answer groups run two columns. The seller's answers are short label/value pairs; one column on a 1000px content area would be a ribbon of white space. The groups, their icons and their order still come from the server (field_groups), untouched.
  • Similar properties is a carousel, like every other section in this set.

B · Owner view — Desktop 1440 (own listing: stats, edit, Mark as Sold)

Owner view

  • The same page. The contact panel is replaced by the owner panel: Views · Saves · Leads (the app's own three counts), Edit, Boost, Mark as Sold, and the status chip (Live / Under Review / Sold).
  • Nothing about the buyer-facing body changes, so an owner always sees exactly what a buyer sees — which is the point of the app's "view as visitor" affordance.
