01 · The shell
Two chromes. Public pages get the current project's header, ported as-is. Signed-in work gets a 240px sidebar carrying the live app's own destinations — the Dashboard hub's nine (lib/dashboard/items.ts) plus the profile sheet's rows. Bottom nav retires at 768.

A · Console chrome — Desktop 1440 (seller signed in, role: owner)

What changed, and why

  • Every entry gate is visible at once. On mobile the destinations hide in two sheets — the Dashboard hub (the feed header's grid icon) and the profile sheet. A sheet is right on a phone and wrong on a 1440 screen, so the sidebar simply shows them: all nine hub destinations plus Saved, Your activity, Drafts, Archived, Help and Settings. No sheet, no hub screen, no extra tap.
  • The bottom nav retires above 768. Its five destinations are re-homed — Home and Search at the top of the sidebar, Create as the accent button in the top bar, Leads in Inventory, Profile in the user block. Nothing becomes unreachable.
  • The counts stay honest. Same badges the mobile hub shows, same /feed/badges call, and the two "waiting on you" ones (Leads, My visits) keep the solid ink pill instead of the accent one, exactly as lib/dashboard/items.ts defines with urgent.
  • Right rail (320). Plan usage and quick actions sit below the fold on mobile because there is nowhere else; on desktop they belong beside the content, sticky.
  • Role rule preserved. A builder loses Search here exactly as the bottom nav already drops it. The nine tiles stay unfiltered and entitlement-gated, as the code comment requires.
  • Tiles are a carousel, not a grid — the owner rule applies to the console too.

B · Console chrome — Tablet 1024 (same markup, 72px icon rail)

Tablet is not a small desktop

  • The sidebar collapses to a 72px icon rail — same order, same badges, labels on hover. A 240px sidebar on a 1024 screen spends a quarter of the width on text the user already knows.
  • The right rail folds back into the content column, so plan usage stays above the fold instead of being pushed to the bottom.
  • Carousels show 2 cards instead of 3–4; nothing is stretched to fill.

C · Public chrome — Desktop 1440 (the current project's header, ported)

The public header

  • Ported straight from components/shell/Header.tsx in the current project: logo + city on the left, the primary nav centred, and on the right Dashboard · bell · saved · avatar · the accent Post Property. Guests get "Log in" and Post Property with the FREE* flag, same as there.
  • The nav items are the live app's own categories — Buy · Rent · Projects · Commercial · Plots · PG · Requirements — from lib/listings/type-icon.ts and the Buy/Rent filter.
  • Under 1080 the nav folds into the hamburger, exactly as the current header does; the drawer carries the same list plus the account rows.
  • Stories. A 9:16 story stretched across a 1440 screen looks broken, so opening one gives a centred 400×710 player on a dimmed page, previous/next posters as small cards either side, arrow keys wired. Detail in 07-story-viewer.html.
  • Guest gate. Any gated action opens the log-in as a centred modal instead of a route jump, so the visitor never loses the page they were on. Detail in 02-auth-entry.html.
