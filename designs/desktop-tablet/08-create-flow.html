08 · Create flow
Real flow and real copy: Create → Property type (step dots 1–4) → Form → Photos ("Add photos", "Set as cover", "Continue to Preview") → Preview ("Feed card" / "Full listing", "Submit for Review") → "Listing submitted". Type codes are the app's own.

A · Create → what are you posting — Desktop 1440

Decisions

  • The 4-step flow becomes a visible stepper. Mobile shows four dots in the header; desktop shows the named steps — Type · Details · Photos · Preview — so the seller knows how much is left before they start typing. Same four steps, same routes.
  • Form on the left, live preview on the right (380). This is the single biggest thing desktop can add: the seller sees the feed card and the full listing building itself as they type. It uses the app's existing Preview component, which already renders both — nothing new to build, just mounted beside the form instead of behind a Continue button.
  • Fields go two-up, never wider. The form column caps at 760 because a 1200px-wide text input is unusable. Short pairs (Bedrooms / Bathrooms, Built-up / Carpet) sit side by side; long ones stay full width. Field order, labels and validation stay exactly as the server's field_definitions defines them.
  • Photos gets a real grid of thumbs — this is the one place a fixed tile layout is correct, because it is an upload tray, not a content list. Cover badge, "Set as cover" and the retry state are the app's own.
  • The slot line stays visible. "1 listing slot left on Owner Pro" rides the top of the flow, because running out mid-form is the worst moment to find out.
