Decisions

  • The profile is a page, not a sheet. On mobile the account rows hide behind the profile sheet; on desktop those rows are already in the sidebar, so this page is what a visitor sees — which is exactly what the owner should be looking at when they edit it.
  • Header, stats and tabs across the top — Listings · Projects · Requirements · Featured, with the app's own counts and its own empty states ("No listings yet", "Nothing here yet").
  • Featured collections keep their circles, as a carousel.
  • Edit is form + live profile preview: the seller sees the public card change as they type, which is the same pattern as the create flow, so there is one idea to learn, not two.
  • Verification becomes a visible checklist instead of a stack of screens: Phone · ID · RERA, each with its state, its document type list and its re-upload path. The app's own review copy ("Under review — usually within 24 hours", "Please re-upload") is kept word for word.
  • Other people's profiles use the same page minus the owner actions, plus Copy link, Block user and the report reasons the app already defines.
