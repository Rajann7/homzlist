## The device bands, machine-checked

`scripts/check-p13-bands.mjs` drives the prototype through every screen × band
and asserts the design frame really renders at 390 / 768 / 1440. Two things it
caught that would have silently corrupted every later pixel-diff:

- The prototype floats its frame on a 24px "desk" (`deskPad`, template 416) and
  the frame is `max-width:100%`. A 768px browser window therefore renders a
  **720px** "tablet" — the wrong band, quietly. Both this script and
  `scripts/pixdiff.mjs` now flatten that desk before measuring or shooting.
- Reloading the page per state cost ~15s (Babel compiles the prototype in-page).
  The device state is React state, so the page is loaded once and driven with
  `setState`: 81 states in about a minute.

```bash
node scripts/check-p13-bands.mjs            # all 27 screens × 3 bands
node scripts/check-p13-bands.mjs users      # one screen
```

Last run: **all 81 screen×band states rendered at the design's width**, no
page-level horizontal scroll in any of them.

### What that run also revealed (carry into P3/P7)

Several screens have **no mobile card branch** — the design keeps a full table at
390 and lets the table's own box scroll. Widest table measured at mobile:

```
tickets 941 · trash 856 · exports 839 · disputes 746 · staff 731
requirements 664 · boosts 659 · cron 623 · templates 618 · cms 613
settings 570 · verifications 504
```

That is the design's behaviour and must be reproduced, not "fixed" with an
invented card list. The page itself never scrolls sideways in any of them.

**Resolved with Rajan** — A3 Listings queue at TABLET: the table measures 1071px
inside a ~528px content column, and the design's `queueTable` (template 821)
wraps it in `overflow:hidden`, so those columns were *clipped* — an admin could
not reach Status at all on a 768–1439px screen. Fixed to `overflow:auto`, which
clips identically whenever content fits, so the appearance is unchanged and only
the dead end goes away. The twelve table-on-mobile screens above are reproduced
as drawn.

`--accentDis` also differed (design `#2A5A40` dark, Doc1 `#a8d5bd`). The design's
value wins, scoped to admin only.

### Scope note — what P0 deliberately does NOT close

§1 says P0 ships **no screens**, so five of §9's seven gates (pixel diff, control
checklist, click-flow replay, PROOF.md's 5 gates, security sweep) have nothing to
run against yet. They are not skipped — they land with P2, which is the first
part that mounts the shell on a route.

Concretely, the header's bell / search / avatar are rendered by the shell but
their data and endpoints belong to P2: there is no admin identity to authorize
them against until A1 exists. The shell therefore takes them as render props and
takes its badge counts as required props — there is no default, no placeholder
number and no mock array anywhere in P0.

### Export and bulk

- **Export** — `lib/admin/export.ts`, `ExportModal`, `POST /api/v1/admin/export`.
  Real CSV and real XLSX (`exceljs` added). It re-runs the table's own query and
  pages through the WHOLE filtered set, writes to a private bucket of its own
  (migration 0092), records `contains_personal_data`, and audits as sensitive.
- **Bulk** — `lib/admin/bulk.ts`, `POST /api/v1/admin/bulk/:resource/:action`.
  A registry, so P3 registers actions rather than building machinery. The cap is
  enforced server-side as well as in the bar, and every subject gets its OWN
  audit row — "bulk approve ×12" cannot answer "who approved #4521". Subjects
  apply independently, so one locked row does not abort the batch.

```
export CSV  action=approve  → 82 rows · 7,625B · headers Time,Admin,Action,Entity,Summary
export XLSX severity=true   → 320 rows · 18,504B · sheet "audit"
            both downloaded back and parsed; row counts match the exports row
            public URL probe on the bucket → 400 (not publicly readable)
            exports row: ready · file_key · contains_personal_data · 7-day expiry
            admin_audit_log: action=export · is_sensitive=true · filters+fields in diff
staff role attempting an export → 403
```

### Three real bugs the proof caught

1. **Storage rejected the upload.** `private-docs` has a deliberately tight mime
   allowlist (images + pdf) because it holds ID scans and ownership proofs.
   Widening it for spreadsheets would have loosened a guard on an unrelated
   user-upload path, so exports got their own private bucket (0092). While it was
   broken the compensating path did its job: the `exports` row went to `failed`
   with a reason rather than vanishing.
2. **The key double-prefixed** — `admin-exports/<id>` inside bucket
   `admin-exports`. Harmless until a download looks in the obvious place and
   finds nothing. The key is now just the id.
3. **Every exported column was blank except two.** The column keys were UI names
   (`time`, `admin`, `entity`) while the rows carry `created_at`, `actor_name`,
   `entity_label` — only `action` and `summary` happened to match. A resource now
   declares `columns: {key, label, field}`, so the UI name, the header text and
   the data key are three separate things by construction. This would otherwise
   have shipped as a silently useless export.

Nothing here is mounted on a screen yet: the audit resource these were proven
against is A26, which belongs to P7. The controls get their pixel-diff,
click-flow and 5-gate proof when P3 stands up the first queue screen.

### The design's controls, made real

- **7d / 30d / 6m** re-queries per range (day · week · month buckets), it does
  not re-slice one payload.
- **Banner ×** persists to `anomaly_events.dismissed_at` with the admin's id and
  an audit row. The design dismisses into component state, which would have come
  back on reload and been per-admin.
- **My profile** writes name, phone and both switches to `staff`; email and role
  are read-only in the sheet AND ignored by the endpoint — they are the
  whitelist.
- **Switch account** is a real device-local pool (`hz_admin_accts`) mirroring
  lib/auth/account-pool: park, list against live KV sessions, rotate in.
- **Overdue rows / tiles / banners / bell rows** all deep-link; nothing 404s,
  because unbuilt screens render the design's placeholder.

**Two harness fixes were needed first**, and both would have corrupted every
later admin diff:
- P13 floats its frame on a 24px "desk" and P13's DEV panel is `position:

  browser default.** A 15px nav row measured 41px against the design's 38 — a
  3px error repeated down every row of every admin screen. `.admin-scope` in
  `admin.css` restores `normal` for the admin subtree only. This alone took A1
  from 3.06% to 0.39% at mobile.
